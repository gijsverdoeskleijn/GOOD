# Data, software, and provenance

GOOD documentation and analysis outputs should be findable, accessible under
stated conditions, interoperable through explicit formats and semantics, and
reusable through licensing, provenance, and sufficient technical context.

Each reproducible analysis record should identify:

- input datasets, identifiers, versions, checksums, and access conditions;
- software repositories, commits or releases, dependencies, and environment;
- configuration values, models, reference frames, units, and time standards;
- workflow definition and execution identifiers;
- produced datasets and reports, including uncertainties;
- responsible person or service and execution time;
- licences, citations, retention, and permissible reuse.

The documentation build manifest applies the same principle to this portal by
recording the documentation revision, registered source baselines, active
profile, timestamp, and content digests.
